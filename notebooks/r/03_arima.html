1. Manual identification

Same reading as in Python. In Phase 2, the ACF of the log price decays slowly (d = 1), and returns show no significant autocorrelation (Ljung-Box not rejected). The model proposed by hand is therefore ARIMA(0,1,0) without drift (a random walk). ARIMA(0,1,1) serves as a competitor.

2. Automatic search: forecast::auto.arima

ic = "aic" is imposed to be comparable with pmdarima (R’s default is AICc). The search is run once with d = 1 imposed, once with free d (auto.arima then chooses d with a KPSS test).

# Stepwise search like pmdarima; approximation = FALSE so the likelihood is exact, as in statsmodels.
auto_tab <- do.call(rbind, lapply(names(y_tr), function(s) {
  a1 <- auto.arima(y_tr[[s]], d = 1, seasonal = FALSE, ic = "aic", stepwise = TRUE, approximation = FALSE)
  a2 <- auto.arima(y_tr[[s]], seasonal = FALSE, ic = "aic", stepwise = TRUE, approximation = FALSE)
  data.frame(series = s, setting = c("d = 1 imposed", "free d"),
             order = c(paste(arimaorder(a1), collapse = ","), paste(arimaorder(a2), collapse = ",")),
             drift = c("drift" %in% names(coef(a1)), "drift" %in% names(coef(a2))),
             AIC = c(a1$aic, a2$aic), BIC = c(a1$bic, a2$bic))
}))
write.csv(auto_tab, file.path(RES, "03_auto_arima_r.csv"), row.names = FALSE)

3. Seasonality (s = 5)

# Seasonal differencing tests (OCSB, and R's default "seas" = STL seasonal strength; Canova-Hansen would need the extra uroot package) and nested LR tests of seasonal AR / MA terms, as in Python.
seas <- do.call(rbind, lapply(names(y_tr), function(s) {
  yts <- ts(y_tr[[s]], frequency = 5)
  base <- Arima(yts, order = c(0, 1, 0), method = "ML")
  rows <- data.frame(series = s, model = "ARIMA(0,1,0)", AIC = base$aic, BIC = base$bic, LR = NA, df = 0, p_value = NA,
                     D_ocsb = nsdiffs(yts, test = "ocsb"), D_seas = nsdiffs(yts, test = "seas"))
  for (so in list(c(1, 0, 0), c(0, 0, 1), c(1, 0, 1))) {
    f <- Arima(yts, order = c(0, 1, 0), seasonal = list(order = so, period = 5), method = "ML")
    lr <- 2 * (f$loglik - base$loglik); df <- sum(so)
    rows <- rbind(rows, data.frame(series = s, model = sprintf("SARIMA(0,1,0)(%d,%d,%d)[5]", so[1], so[2], so[3]),
                                   AIC = f$aic, BIC = f$bic, LR = lr, df = df, p_value = pchisq(lr, df, lower.tail = FALSE),
                                   D_ocsb = NA, D_seas = NA))
  }
  rows
}))
write.csv(seas, file.path(RES, "03_seasonal_tests_r.csv"), row.names = FALSE)

4. Chosen models and residual diagnostics

# method = "ML" (exact likelihood) to match statsmodels; no drift, as chosen in Python.
fits <- list()
for (s in names(y_tr)) {
  fits[[paste(s, "ARIMA(0,1,0)")]] <- Arima(y_tr[[s]], order = c(0, 1, 0), method = "ML")
  fits[[paste(s, "ARIMA(0,1,1)")]] <- Arima(y_tr[[s]], order = c(0, 1, 1), method = "ML")

5. Forecast from the first origin (cross-check)

The rolling-origin forecasts in the common file results/forecasts_arima.csv are produced by Python. Here, R recomputes the forecast from the first origin (the last training day), for h = 1 to 10, and compares it with Python’s.

# Forecast 10 steps from the last train day, map back to index points with exp(), and compare with Python's first origin.
py_fc <- read.csv(file.path(RES, "forecasts_arima.csv"))
origin0 <- cfg$split$train_end
cmp <- do.call(rbind, lapply(list(c("CONVERTS", "rw", "ARIMA(0,1,0)"), c("CONVERTS", "arima_011", "ARIMA(0,1,1)"),
                                  c("PURE", "rw", "ARIMA(0,1,0)"), c("PURE", "arima_011", "ARIMA(0,1,1)")), function(k) {
  fc <- forecast(fits[[paste(k[1], k[3])]], h = 10, level = 95)
  p <- py_fc[py_fc$series == k[1] & py_fc$model == k[2] & py_fc$origin == origin0, ]
  p <- p[order(p$horizon), ]
  data.frame(series = k[1], model = k[2], horizon = 1:10,
             y_pred_R = exp(as.numeric(fc$mean)), y_pred_Py = p$y_pred,
             lower_R = exp(as.numeric(fc$lower)), lower_Py = p$lower,
             upper_R = exp(as.numeric(fc$upper)), upper_Py = p$upper)
}))
cmp$reldiff_pred <- abs(cmp$y_pred_R / cmp$y_pred_Py - 1)
cmp$reldiff_upper <- abs(cmp$upper_R / cmp$upper_Py - 1)
write.csv(cmp, file.path(RES, "forecasts_arima_r_first_origin.csv"), row.names = FALSE)

Conclusion of the comparison.

  • Same orders. auto.arima with d = 1 gives (0,1,0) for CONVERTS and (0,1,0) for PURE, without drift, like pmdarima.
  • Free d. When d is left free, R chooses (5,2,0) for CONVERTS (Python: (5,2,1)). The difference comes from the KPSS test used by default to choose d (see the Python notebook).
  • Same coefficients. The maximum relative difference on the coefficients and on σ² is 0.015. The maximum log-likelihood difference is 0.00019.
  • Same forecasts. The maximum relative difference on the forecast from the first origin is 5.5e-05, and 0.00024 on the upper bound of the 95% interval.

The two implementations therefore reach the same model and the same conclusions. The small numerical differences come from the optimiser and from how the likelihood of an integrated model is initialised (diffuse Kalman filter in statsmodels, prior differencing in R).
